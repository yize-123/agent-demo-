# 从零开发 AI Agent 项目 - 视频讲解式教程

> 本文档模拟视频讲解的方式，带你一步步理解为什么要这样写代码，以及每个模块之间的依赖关系。

---

## 开篇：项目整体规划

### 我们要做什么？

我们要开发一个 **AI Agent** 项目，它能够：
1. 接收用户的消息
2. 判断是否需要调用工具
3. 执行工具并获取结果
4. 整合结果回答用户

### 项目架构预览

在开始写代码之前，我们先规划好整体架构：

```
用户输入
    ↓
Controller（接收请求）
    ↓
ReActAgent（核心大脑）
    ↓
OpenAIService（调用LLM）
    ↓
ToolRegistry → 具体Tool（执行工具）
    ↓
返回结果给用户
```

### 模块依赖关系

**重要**：以下顺序不能乱，因为后面的模块依赖前面的模块！

```
1. Model层（数据模型）     ← 最底层，不依赖其他模块
2. Tools层（工具实现）     ← 依赖 Model层的 Tool接口
3. Service层（服务）       ← 依赖 Model层 和 Tools层
4. Agent层（核心逻辑）     ← 依赖 Service层
5. Controller层（接口）    ← 依赖 Agent层
6. 前端页面               ← 依赖 Controller层
```

## 第一阶段：搭建项目骨架

### 为什么先写 pom.xml？

**原因**：pom.xml 是项目的"地基"，它定义了：
- 项目用什么版本的 Java
- 需要哪些依赖库
- 如何构建项目

**如果不先写 pom.xml**：
- IDE 无法识别项目
- 无法导入需要的库
- 无法编译和运行

### 创建 application.yml

**为什么需要配置文件？**

配置文件用于存储：
- 服务器端口
- API 密钥
- 各种参数

**为什么不写在代码里？**
- 配置和代码分离，方便修改
- 不同环境（开发/测试/生产）可以用不同配置
- 敏感信息（如 API Key）不应该写在代码里

```yaml
# 服务器配置
server:
  port: 8080  # 项目运行的端口

# OpenAI 配置
openai:
  api-key: ${OPENAI_API_KEY}  # 从环境变量读取，不要硬编码
  model: gpt-3.5-turbo-0613   # 使用的模型
  temperature: 0.7            # 回答的随机性，0-1之间
  base-url: https://api.openai.com  # API 地址

# Agent 配置
app:
  agent:
    max-tool-calls: 5  # 最大工具调用次数，防止无限循环
```

## 第二阶段：创建 Model 层

### 为什么先写 Model 层？

**原因**：Model 层是数据的"载体"，其他所有层都要用到它。

**类比**：就像盖房子，Model 层是"砖块"，其他层是用砖块盖起来的"房间"。

### 创建 Message.java

**为什么需要 Message 类？**

因为 OpenAI API 的对话是基于"消息列表"的，每条消息包含：
- role：谁说的（user/assistant/system/tool）
- content：说了什么

```java
package com.example.aigent.model;

import com.fasterxml.jackson.annotation.JsonProperty;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

/**
 * 对话消息模型
 * 
 * 这个类表示对话中的一条消息
 * OpenAI API 要求消息格式为：{"role": "xxx", "content": "xxx"}
 */
@Data                    // Lombok 自动生成 getter/setter/toString/equals/hashCode
@Builder                 // Lombok 自动生成建造者模式
@NoArgsConstructor       // Lombok 自动生成无参构造函数
@AllArgsConstructor      // Lombok 自动生成全参构造函数
public class Message {
    
    /**
     * 消息角色
     * 
     * OpenAI API 支持四种角色：
     * - system：系统消息，用于设置 AI 的行为
     * - user：用户消息
     * - assistant：AI 回复
     * - tool：工具执行结果
     */
    private String role;
    
    /**
     * 消息内容
     */
    private String content;
    
    /**
     * 工具名称
     * 
     * 当 role 为 "tool" 时，需要指定是哪个工具返回的结果
     * @JsonProperty("name") 表示在 JSON 中这个字段叫 "name"
     */
    @JsonProperty("name")
    private String toolName;
    
    /**
     * 工具调用 ID
     * 
     * OpenAI 要求工具返回结果时，必须带上调用时的 ID
     * 这样才能把结果和调用对应起来
     */
    @JsonProperty("tool_call_id")
    private String toolCallId;
    
    /**
     * 创建用户消息的静态方法
     * 
     * 为什么用静态方法而不是 new Message()？
     * 1. 更简洁：Message.user("你好") vs new Message("user", "你好", null, null)
     * 2. 更清晰：一看就知道是创建用户消息
     * 3. 避免错误：不会把 role 写错
     */
    public static Message user(String content) {
        return Message.builder()
                .role("user")
                .content(content)
                .build();
    }
    
    /**
     * 创建助手消息
     */
    public static Message assistant(String content) {
        return Message.builder()
                .role("assistant")
                .content(content)
                .build();
    }
    
    /**
     * 创建工具消息
     * 
     * 工具消息比较特殊，需要三个参数：
     * - toolName：哪个工具
     * - content：返回了什么
     * - toolCallId：对应哪次调用
     */
    public static Message tool(String toolName, String content, String toolCallId) {
        return Message.builder()
                .role("tool")
                .toolName(toolName)
                .content(content)
                .toolCallId(toolCallId)
                .build();
    }
    
    /**
     * 创建系统消息
     * 
     * 系统消息用于"告诉 AI 它是谁、该怎么做"
     * 通常放在消息列表的第一条
     */
    public static Message system(String content) {
        return Message.builder()
                .role("system")
                .content(content)
                .build();
    }
}
```

### 创建 Tool.java 接口

**为什么需要 Tool 接口？**

**设计思想**：我们不知道未来会有多少种工具，所以定义一个"标准"，所有工具都按这个标准来实现。

**类比**：就像 USB 接口，不管是什么设备（鼠标、键盘、U盘），只要符合 USB 标准，就能插上电脑使用。

```java
package com.example.aigent.model;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.node.ArrayNode;
import com.fasterxml.jackson.databind.node.ObjectNode;

/**
 * 工具接口
 * 
 * 这是 AI Agent 的核心设计之一
 * 所有工具（搜索、读取文件、管理待办等）都必须实现这个接口
 * 
 * 为什么用接口而不是抽象类？
 * 1. 接口更灵活，一个类可以实现多个接口
 * 2. 接口没有状态，更符合"工具"的概念
 * 3. 方便扩展，新增工具只需要实现接口
 */
public interface Tool {
    
    /**
     * 获取工具名称
     * 
     * 这个名称会发送给 OpenAI，让 AI 知道有哪些工具可用
     * 例如："web_search"、"read_file"
     * 
     * 命名规范：小写字母，下划线分隔
     */
    String getName();
    
    /**
     * 获取工具描述
     * 
     * 这个描述非常重要！
     * OpenAI 会根据描述来决定是否调用这个工具
     * 
     * 描述要写清楚：
     * 1. 这个工具做什么
     * 2. 什么时候应该用
     * 3. 能解决什么问题
     */
    String getDescription();
    
    /**
     * 获取参数定义（JSON Schema 格式）
     * 
     * OpenAI 需要知道调用工具需要哪些参数
     * 例如 web_search 需要 query 参数
     * 
     * 返回的是 JSON Schema 格式，例如：
     * {
     *   "type": "object",
     *   "properties": {
     *     "query": {"type": "string", "description": "搜索关键词"}
     *   },
     *   "required": ["query"]
     * }
     */
    JsonNode getParameters();
    
    /**
     * 执行工具
     * 
     * 这是工具的核心方法
     * 
     * @param arguments 参数，从 OpenAI 返回的 JSON 字符串解析而来
     * @return 执行结果，JSON 字符串格式
     */
    String execute(JsonNode arguments);
    
    /**
     * 转换为 OpenAI 工具格式
     * 
     * OpenAI 要求工具格式为：
     * {
     *   "type": "function",
     *   "function": {
     *     "name": "工具名",
     *     "description": "描述",
     *     "parameters": {...}
     *   }
     * }
     * 
     * 这个方法就是生成这个格式
     * 
     * 为什么用 default 方法？
     * 因为所有工具的转换逻辑都一样，不需要每个工具单独实现
     */
    default ObjectNode toOpenAITool(ObjectMapper mapper) {
        ObjectNode toolObject = mapper.createObjectNode();
        toolObject.put("type", "function");
        
        ObjectNode functionObject = mapper.createObjectNode();
        functionObject.put("name", getName());
        functionObject.put("description", getDescription());
        functionObject.set("parameters", getParameters());
        
        toolObject.set("function", functionObject);
        return toolObject;
    }
    
    /**
     * 创建参数 Schema 的辅助方法
     * 
     * 这个方法是为了简化参数定义的代码
     * 不用每个工具都写一遍创建 JSON 的代码
     */
    static ObjectNode createParameters(ObjectMapper mapper, ObjectNode properties, String... required) {
        ObjectNode params = mapper.createObjectNode();
        params.put("type", "object");
        params.set("properties", properties);
        
        // 添加必填字段列表
        ArrayNode requiredArray = mapper.createArrayNode();
        for (String field : required) {
            requiredArray.add(field);
        }
        params.set("required", requiredArray);
        
        return params;
    }
}
```

### 创建 AgentResponse.java

**为什么需要 AgentResponse？**

Controller 需要返回数据给前端，但直接返回字符串不够用，我们需要返回更多信息：
- 回答内容
- 是否调用了工具
- 调用了哪些工具
- 响应时间

```java
package com.example.aigent.model;

import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.util.List;

/**
 * Agent 响应模型
 * 
 * 这个类封装了 Agent 的完整响应
 * 返回给前端的数据就是这个类的 JSON 格式
 */
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class AgentResponse {
    
    /**
     * 会话 ID
     * 
     * 用于标识一次完整的对话
     * 前端需要保存这个 ID，下次发送消息时带上
     * 这样 Agent 才能知道是同一个对话
     */
    private String conversationId;
    
    /**
     * 最终回答
     */
    private String answer;
    
    /**
     * 思考过程
     * 
     * ReAct 框架的特点是"推理-行动"
     * 这个列表记录了 Agent 的思考过程
     * 例如：["用户输入: ...", "思考: 需要调用工具", "工具返回: ..."]
     */
    private List<String> thoughts;
    
    /**
     * 使用的工具列表
     * 
     * 记录本次对话调用了哪些工具
     * 例如：["web_search", "read_file"]
     */
    private List<String> toolsUsed;
    
    /**
     * 是否使用了工具
     */
    private boolean toolUsed;
    
    /**
     * 响应耗时（毫秒）
     * 
     * 用于性能监控和用户体验优化
     */
    private long responseTimeMs;
    
    /**
     * 创建成功响应的静态方法
     */
    public static AgentResponse success(String conversationId, String answer,
                                       List<String> thoughts, List<String> toolsUsed,
                                       long responseTimeMs) {
        return AgentResponse.builder()
                .conversationId(conversationId)
                .answer(answer)
                .thoughts(thoughts)
                .toolsUsed(toolsUsed)
                .toolUsed(!toolsUsed.isEmpty())  // 如果工具列表不为空，说明使用了工具
                .responseTimeMs(responseTimeMs)
                .build();
    }
    
    /**
     * 创建错误响应的静态方法
     */
    public static AgentResponse error(String errorMessage) {
        return AgentResponse.builder()
                .answer("Error: " + errorMessage)
                .toolUsed(false)
                .responseTimeMs(0)
                .build();
    }
}
```

## 第三阶段：创建工具层

### 为什么现在写工具层？

**原因**：
1. Model 层已经完成，有了 Tool 接口
2. 工具是 Agent 的"手脚"，必须先有工具，Agent 才能干活
3. Service 层（ToolRegistry）需要扫描工具类

### 创建第一个工具：LSRepoTool

**为什么先写这个工具？**

因为它最简单，不依赖外部 API，只是列出目录文件。适合作为第一个练手的工具。

```java
package com.example.aigent.tools;

import com.example.aigent.model.Tool;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.node.ObjectNode;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Stream;

/**
 * 目录列表工具
 * 
 * 功能：列出指定目录下的文件和文件夹
 * 用途：让 Agent 能够探索项目结构
 * 
 * @Slf4j：Lombok 注解，自动生成 log 日志对象
 * @Component：Spring 注解，标记这是一个 Spring 组件
 *             Spring 会自动扫描并创建这个类的实例
 *             ToolRegistry 会自动收集所有 Tool 实现类
 */
@Slf4j
@Component
public class LSRepoTool implements Tool {

    /**
     * 工具名称
     * 
     * 这个名称会发送给 OpenAI
     * AI 会根据这个名称来决定调用哪个工具
     */
    @Override
    public String getName() {
        return "list_directory";
    }

    /**
     * 工具描述
     * 
     * 这个描述非常重要！
     * OpenAI 会根据这个描述来判断是否应该调用这个工具
     * 
     * 描述要写清楚：
     * 1. 这个工具做什么
     * 2. 什么时候应该用
     */
    @Override
    public String getDescription() {
        return "列出指定目录下的文件和文件夹，用于探索项目结构。参数：directory（可选，默认当前目录）";
    }

    /**
     * 参数定义
     * 
     * 定义这个工具需要什么参数
     * 使用 JSON Schema 格式
     */
    @Override
    public JsonNode getParameters() {
        ObjectMapper mapper = new ObjectMapper();
        ObjectNode params = mapper.createObjectNode();
        params.put("type", "object");
        
        // 定义参数属性
        ObjectNode properties = mapper.createObjectNode();
        
        // directory 参数
        ObjectNode dirParam = mapper.createObjectNode();
        dirParam.put("type", "string");
        dirParam.put("description", "要列出的目录路径，默认为当前目录");
        properties.set("directory", dirParam);
        
        params.set("properties", properties);
        // 注意：directory 不是必填的，所以不添加到 required
        return params;
    }

    /**
     * 执行工具
     * 
     * 这是工具的核心方法
     * 
     * @param arguments 从 OpenAI 返回的参数
     * @return JSON 格式的执行结果
     */
    @Override
    public String execute(JsonNode arguments) {
        try {
            // 1. 获取参数，如果没有指定目录，使用当前目录
            String directory = arguments.has("directory")
                    ? arguments.get("directory").asText()
                    : System.getProperty("user.dir");  // 获取当前工作目录

            // 2. 列出目录内容
            Path path = Paths.get(directory);
            List<String> items = new ArrayList<>();

            // 使用 try-with-resources 自动关闭流
            try (Stream<Path> stream = Files.list(path)) {
                // 限制最多列出 50 个，防止目录太大
                stream.limit(50).forEach(p -> {
                    // 判断是文件还是目录
                    String type = Files.isDirectory(p) ? "[dir]  " : "[file] ";
                    items.add(type + p.getFileName());
                });
            }

            // 3. 返回 JSON 格式的结果
            // 为什么返回 JSON？因为方便 Agent 解析和处理
            return "{\"directory\": \"" + directory + "\", \"items\": [" +
                    String.join(",", items.stream().map(s -> "\"" + s + "\"").toList()) +
                    "]}";
                    
        } catch (Exception e) {
            // 记录错误日志
            log.error("list_directory 执行失败", e);
            // 返回错误信息，也是 JSON 格式
            return "{\"error\": \"" + e.getMessage() + "\"}";
        }
    }
}
```

### 接下来要写什么？

按照同样的模式，创建其他工具：
1. ReadFileTool - 读取文件内容
2. TodoManagerTool - 管理待办事项
3. FetchFromWebTool - 抓取网页
4. WebSearchTool - 搜索（模拟）

**每个工具的结构都一样**：
1. getName() - 返回工具名
2. getDescription() - 返回描述
3. getParameters() - 返回参数定义
4. execute() - 执行逻辑

## 第四阶段：创建 Service 层

### 为什么现在写 Service 层？

**原因**：
1. Model 层完成 ✓
2. Tools 层完成 ✓
3. Service 层需要管理工具（ToolRegistry）和调用 OpenAI（OpenAIService）

### 创建 ToolRegistry

**ToolRegistry 的作用**：
- 收集所有工具
- 根据名称查找工具
- 生成 OpenAI 需要的工具列表格式

```java
package com.example.aigent.service;

import com.example.aigent.model.Tool;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.node.ArrayNode;
import com.fasterxml.jackson.databind.node.ObjectNode;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 工具注册中心
 * 
 * 这个类负责管理所有工具
 * 
 * 工作原理：
 * 1. Spring 启动时，自动扫描所有 @Component 且实现 Tool 接口的类
 * 2. 通过构造函数注入，Spring 会把所有 Tool 实现类传进来
 * 3. 我们把它们存到 Map 里，方便按名称查找
 */
@Slf4j
@Service
public class ToolRegistry {

    // 用 Map 存储工具，key 是工具名，value 是工具实例
    private final Map<String, Tool> tools = new HashMap<>();
    private final ObjectMapper objectMapper;

    /**
     * 构造函数
     * 
     * Spring 会自动调用这个构造函数
     * List<Tool> toolList 会自动注入所有 Tool 实现类
     * 
     * 这是 Spring 的依赖注入特性，非常方便！
     */
    public ToolRegistry(List<Tool> toolList, ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;
        
        // 遍历所有工具，存入 Map
        for (Tool tool : toolList) {
            tools.put(tool.getName(), tool);
            log.info("工具已注册: {}", tool.getName());
        }
        
        log.info("共注册 {} 个工具", tools.size());
    }

    /**
     * 根据名称获取工具
     */
    public Tool getTool(String name) {
        return tools.get(name);
    }

    /**
     * 获取所有工具的 OpenAI 格式描述
     * 
     * 这个方法很重要！
     * OpenAI 要求工具列表是特定格式
     */
    public ArrayNode getToolsAsJsonSchema() {
        ArrayNode arrayNode = objectMapper.createArrayNode();
        
        for (Tool tool : tools.values()) {
            // 调用 Tool 接口的 toOpenAITool 方法
            arrayNode.add(tool.toOpenAITool(objectMapper));
        }
        
        return arrayNode;
    }
}
```

## 第五阶段：创建 Agent 核心类

### 为什么现在写 Agent？

**原因**：
1. 所有依赖都已准备好：
   - Model 层 ✓
   - Tools 层 ✓
   - Service 层 ✓
2. Agent 是"大脑"，需要调用所有其他组件

### ReActAgent 核心逻辑

**ReAct 是什么？**

ReAct = Reasoning（推理）+ Acting（行动）

**工作流程**：
1. 用户提问
2. AI 思考：是否需要工具？
3. 如果需要，调用工具
4. 获取工具结果
5. AI 再思考：还需要其他工具吗？
6. 重复 3-5，直到不需要工具
7. 生成最终回答

```java
package com.example.aigent.agent;

import com.example.aigent.model.*;
import com.example.aigent.service.ConversationHistory;
import com.example.aigent.service.OpenAIService;
import com.example.aigent.service.ToolRegistry;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;

/**
 * ReAct Agent 核心实现
 * 
 * 这是整个项目的"大脑"
 * 
 * 它的工作流程：
 * 1. 接收用户消息
 * 2. 调用 OpenAI 判断是否需要工具
 * 3. 如果需要，执行工具
 * 4. 把工具结果返回给 OpenAI
 * 5. 重复 2-4，直到 OpenAI 认为不需要工具
 * 6. 生成最终回答
 */
@Slf4j
@Component
public class ReActAgent {

    // 依赖注入：需要的服务
    private final OpenAIService openAIService;
    private final ToolRegistry toolRegistry;
    private final ConversationHistory conversationHistory;
    private final ObjectMapper objectMapper;
    
    /**
     * 最大工具调用次数
     * 
     * 为什么要限制？
     * 防止 AI 陷入无限循环，一直调用工具
     * 
     * 从配置文件读取，默认 5 次
     */
    @Value("${app.agent.max-tool-calls:5}")
    private int maxToolCalls;

    public ReActAgent(OpenAIService openAIService, 
                      ToolRegistry toolRegistry,
                      ConversationHistory conversationHistory,
                      ObjectMapper objectMapper) {
        this.openAIService = openAIService;
        this.toolRegistry = toolRegistry;
        this.conversationHistory = conversationHistory;
        this.objectMapper = objectMapper;
    }

    /**
     * 系统提示词
     * 
     * 这个提示词会告诉 AI：
     * 1. 它是谁
     * 2. 它有什么能力
     * 3. 它应该怎么工作
     */
    private static final String REACT_SYSTEM_PROMPT = """
        你是一个AI Agent，具备使用工具的能力。
        
        可用工具：
        {tool_descriptions}
        
        请按照以下方式工作：
        1. 分析用户问题
        2. 判断是否需要调用工具
        3. 如果需要，选择合适的工具执行
        4. 根据工具结果回答用户
        """;

    /**
     * 执行 Agent 对话
     * 
     * 这是最核心的方法！
     * 
     * @param conversationId 会话 ID（可为 null）
     * @param userInput 用户输入
     * @return Agent 响应
     */
    public AgentResponse execute(String conversationId, String userInput) {
        long startTime = System.currentTimeMillis();
        List<String> thoughts = new ArrayList<>();  // 记录思考过程
        List<String> toolsUsed = new ArrayList<>(); // 记录使用的工具
        
        try {
            // 1. 处理会话 ID
            if (conversationId == null || conversationId.isEmpty()) {
                conversationId = conversationHistory.createConversation();
                log.info("创建新对话: {}", conversationId);
            }
            
            // 2. 保存用户消息
            conversationHistory.addMessage(conversationId, Message.user(userInput));
            thoughts.add("用户输入: " + userInput);
            
            // 3. 构建消息列表（包含系统提示词和历史消息）
            List<Message> messages = buildMessages(conversationId);
            
            // 4. ReAct 循环
            int toolCallCount = 0;
            boolean continueLoop = true;
            
            while (continueLoop && toolCallCount < maxToolCalls) {
                // 4.1 调用 OpenAI，询问是否需要工具
                ToolCall toolCall = openAIService.chatCompletionWithTools(
                    messages, 
                    toolRegistry.getToolsAsJsonSchema()
                );
                
                // 4.2 判断是否需要工具
                if (toolCall.isValid()) {
                    // 需要工具
                    thoughts.add("思考: 需要调用工具 " + toolCall.getToolName());
                    log.info("工具调用: {} ({})", toolCall.getToolName(), toolCall.getArguments());
                    
                    // 4.3 执行工具
                    String toolResult = executeTool(toolCall);
                    toolsUsed.add(toolCall.getToolName());
                    thoughts.add("工具返回: " + truncate(toolResult, 200));
                    
                    // 4.4 把工具结果加入消息列表
                    messages.add(Message.assistant("调用工具: " + toolCall.getToolName()));
                    messages.add(Message.tool(toolCall.getToolName(), toolResult, toolCall.getId()));
                    
                    // 4.5 保存到对话历史
                    conversationHistory.addMessage(conversationId, 
                        Message.assistant("调用工具: " + toolCall.getToolName()));
                    conversationHistory.addMessage(conversationId, 
                        Message.tool(toolCall.getToolName(), toolResult, toolCall.getId()));
                    
                    toolCallCount++;
                } else {
                    // 不需要工具，退出循环
                    continueLoop = false;
                }
            }
            
            // 5. 生成最终回答
            String finalAnswer = openAIService.chatCompletion(messages);
            thoughts.add("总结回答: " + truncate(finalAnswer, 200));
            
            // 6. 保存最终回答
            conversationHistory.addMessage(conversationId, Message.assistant(finalAnswer));
            
            // 7. 计算响应时间
            long responseTime = System.currentTimeMillis() - startTime;
            
            // 8. 返回响应
            return AgentResponse.success(conversationId, finalAnswer, thoughts, toolsUsed, responseTime);
            
        } catch (Exception e) {
            log.error("Agent 执行失败: {}", e.getMessage(), e);
            return AgentResponse.error(e.getMessage());
        }
    }

    /**
     * 构建消息列表
     * 
     * 包括：
     * 1. 系统提示词（告诉 AI 它是谁）
     * 2. 历史消息（保持对话连续性）
     */
    private List<Message> buildMessages(String conversationId) {
        List<Message> messages = new ArrayList<>();
        
        // 添加系统提示词
        String toolDescriptions = String.join("\n", toolRegistry.getToolDescriptions());
        String systemPrompt = REACT_SYSTEM_PROMPT.replace("{tool_descriptions}", toolDescriptions);
        messages.add(Message.system(systemPrompt));
        
        // 添加历史消息
        messages.addAll(conversationHistory.getMessages(conversationId));
        
        return messages;
    }

    /**
     * 执行工具调用
     */
    private String executeTool(ToolCall toolCall) {
        // 1. 根据名称获取工具
        Tool tool = toolRegistry.getTool(toolCall.getToolName());
        
        if (tool == null) {
            return "{\"error\": \"未知工具: " + toolCall.getToolName() + "\"}";
        }
        
        try {
            // 2. 解析参数
            JsonNode arguments = objectMapper.readTree(toolCall.getArguments());
            
            // 3. 执行工具
            return tool.execute(arguments);
            
        } catch (Exception e) {
            log.error("工具执行失败: {}", e.getMessage());
            return "{\"error\": \"工具执行失败: " + e.getMessage() + "\"}";
        }
    }

    /**
     * 截断字符串（用于日志显示）
     */
    private String truncate(String text, int maxLength) {
        if (text == null) return "";
        return text.length() > maxLength ? text.substring(0, maxLength) + "..." : text;
    }
}
```

## 第六阶段：创建 Controller 和前端

### 为什么最后写 Controller？

**原因**：
1. Controller 是"门面"，需要调用 Agent
2. 前端是"用户界面"，需要调用 Controller
3. 这是依赖链的最外层

### 创建 AgentController

```java
package com.example.aigent.controller;

import com.example.aigent.agent.ReActAgent;
import com.example.aigent.model.AgentResponse;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

/**
 * Agent REST API 控制器
 * 
 * 这个类提供 HTTP 接口，让前端可以调用 Agent
 * 
 * @RestController = @Controller + @ResponseBody
 * 表示这是一个 REST 接口，返回的是 JSON 数据
 */
@RestController
@RequestMapping("/api/agent")
public class AgentController {

    private final ReActAgent reactAgent;

    public AgentController(ReActAgent reactAgent) {
        this.reactAgent = reactAgent;
    }

    /**
     * 聊天请求的数据结构
     * 
     * 前端发送的 JSON 格式：
     * {
     *   "message": "用户消息",
     *   "conversationId": "会话ID（可选）"
     * }
     */
    @Data
    @NoArgsConstructor
    @AllArgsConstructor
    public static class ChatRequest {
        private String message;
        private String conversationId;
    }

    /**
     * 聊天接口
     * 
     * POST /api/agent/chat
     * 
     * 这是前端调用的主要接口
     */
    @PostMapping("/chat")
    public ResponseEntity<AgentResponse> chat(@RequestBody ChatRequest request) {
        try {
            // 调用 Agent 执行
            AgentResponse response = reactAgent.execute(
                request.getConversationId(), 
                request.getMessage()
            );
            return ResponseEntity.ok(response);
        } catch (Exception e) {
            return ResponseEntity.ok(AgentResponse.error(e.getMessage()));
        }
    }

    /**
     * 健康检查接口
     * 
     * GET /api/agent/health
     * 
     * 用于检查服务是否正常运行
     */
    @GetMapping("/health")
    public ResponseEntity<String> health() {
        return ResponseEntity.ok("{\"status\": \"UP\"}");
    }
}
```

## 总结：开发顺序回顾

### 为什么是这个顺序？

```
1. pom.xml          → 定义项目依赖
2. application.yml  → 配置参数
3. 启动类           → 项目入口
4. Model 层         → 数据结构（被所有层依赖）
5. Tools 层         → 工具实现（依赖 Model）
6. Service 层       → 服务管理（依赖 Model 和 Tools）
7. Agent 层         → 核心逻辑（依赖 Service）
8. Controller 层    → API 接口（依赖 Agent）
9. 前端页面         → 用户界面（依赖 Controller）
```

### 模块间依赖关系图

```
前端页面
    ↓
Controller
    ↓
ReActAgent
    ↓
┌─────────┬─────────────┐
│         │             │
OpenAI   ToolRegistry  ConversationHistory
Service      │             │
    │        ↓             │
    │      Tools           │
    │        │             │
    └────────┴─────────────┘
             │
          Model 层
```

### 核心设计思想

1. **接口设计**：Tool 接口让工具可扩展
2. **依赖注入**：Spring 自动管理组件
3. **分层架构**：Model → Tools → Service → Agent → Controller
4. **ReAct 框架**：推理-行动循环
